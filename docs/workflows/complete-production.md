# 猫咪主活动的三时段完整生产流程

## 1. 唯一链路

```text
Web创作配置 → Day Director → 人工确认DayBrief
→ Morning导演/锚点/视频/人工审核 → 确认Morning实际结果卡
→ Noon导演/锚点/视频/人工审核 → 确认Noon实际结果卡
→ Evening导演/锚点/视频/人工审核 → 确认Evening实际结果卡
→ 01 / 02 / 03交付
```

全天默认`cat_lead`。猫咪通过探索、发现、追逐、等待、误触或自然反应推动观众
注意力；人物负责制作、采摘、垂钓、放线等工具活动或回应；结尾两条活动线汇合。
Web可配置全天默认和每时段覆盖，也可选择`person_lead / balanced / adaptive`。

## 2. 总导演与时段导演

总导演只输出DayBrief：主题、完整全天弧、三个时段的叙事职责、事件方向、外观意图、
活动焦点、自适应时长档与原因，以及跨时段交接。它不写具体动作、镜头或精确秒数。

时段导演读取DayBrief和前序时段结果，输出一个EpisodeScript：

- 一段完整、自然、可阅读的长剧情，包含一个主事件和3～5次因果相连的信息更新。
- 一段关系弧文字，说明猫咪主活动、人物回应与最终汇合。
- 1～3段完整镜头描述；每段同时说明镜头意图、景别、机位、唯一运镜、人物与猫咪
  站位、动作路径、接触对象、可见结果和稳定切点。
- 8～45秒精确时长、外观、环境声、动作声和可见结尾。
- 只在连接、承重、包含、接触、交接或穿戴会决定画面正确性时登记自然语言硬约束；
  普通走动、视线、表情和背景变化不登记。

Morning建立当天活动，Noon推进主要变化，Evening回收前文并形成情绪回报。默认
`guided_sequential`不提前生成后续脚本：中午读取人工确认的上午实际成片结果卡，
傍晚读取上午和中午结果卡。结果卡中的偶发模型错误进入`doNotCarryForward`，不得被
后续导演固化。`auto_day`批量模式才按原始规划摘要连续生成三个时段。

## 3. 分层时长

```text
short    8～15秒   一个 video:single_pass
medium  16～30秒   初始任务 + video:extend:2
long    31～45秒   初始任务 + video:extend:2 + video:extend:3
adaptive           总导演先解析档位，时段导演再选精确秒数
```

每个供应商区段都是8～15秒。延展从上一版视频的末尾状态继续，不重演前文。真实
标准API验证表明，延展返回新增尾段而非包含原片的累计文件；系统因此先独立QC每个
区段，再用FFmpeg `stream copy`按顺序封装为最终成片。该步骤不重新编码，也不等于
逐镜独立生成、创作型`multi_clip`或转码拼接；系统不会为长视频自动切换模型。

## 4. 视觉锚点

每种本集外观生成或复用一张批准定妆图。每集再生成一张9:16开场锚点，输入仅为：

1. 本集定妆图。
2. 定稿灰白猫匹配视角。
3. 室内或户外定稿画风图。
4. 必要时一张已批准关键道具图。

定妆图检查同一中性短发儿童、完整服饰和二维定稿画风。开场锚点还检查一人一猫、
猫咪尾巴比例、活动焦点、相对位置和首镜头动作起点。明确身份、比例、画风或关键
道具错误会阻断视频；低置信转人工。系统不再生成收费故事板组图，文字镜头设计在
Web中直接展示和编辑。

## 5. Seedance Prompt与媒体

视频Prompt只有三段：

```text
【整体设定与素材绑定】
【镜头与动作推进】
【连续性、声音与结尾回报】
```

每段镜头文字完整写出目的与新增信息、景别、机位、唯一运镜、人物与猫咪位置、真实
动作主体、肢体路径、速度、接触对象、可见结果和稳定切点。硬约束按关联镜头投影到
开场锚点、Seedance和媒体审核Prompt，且同一事实在最终Prompt中只出现一次。不输出
数据库ID、JSON字段名、生命周期、完整状态表或绝对时间码。猫咪保持四足生物力学，
不默认操作复杂工具。

完整`storyText`不再重复发给Seedance。初始生成只发送当前RenderSection镜头、相关
硬约束、外观、声音和区段结尾；官方延展只承接上一版视频末帧并执行下一区段，避免
重演前段剧情。视频诊断额外输出实际结果、可继承事实与禁止继承错误，但仍需人工确认。

Web默认编辑结构化脚本并实时预览确定性编译结果，不写库也不调用Ark。高级Prompt
覆盖必须显式开启；脚本变化后覆盖标记为过期，重新确认前不会进入收费请求。节点抽屉
按需加载输入摘要、结构化结果、当前编译Prompt、各attempt实际Prompt、Ark原始JSON、
归一化结果、素材、媒体、审核证据和尝试历史，Run Graph本身保持轻量。

Seedance完成后通过`.part`下载、SHA-256和ffprobe。延展尾段保存为不可变
`video_intermediate`资产；完成区段级QC后，无重编码封装的累计版本保存为`video`并
进入`content_review`。顺序模式在三条人工批准并确认三个实际结果卡后，交付目录固定包含
`01-morning.mp4 / 02-noon.mp4 / 03-evening.mp4 / manifest.json`。

## 6. 固定语义画布与视频时间轴

工作台中央始终显示完整路线。顺序模式的未来时段以锁定节点显示，但不会提前创建导演、
图片或视频Step。节点的可用性与执行状态分开，避免把“未解锁”“未执行”“Provider完成”
和“内容批准”混为一个状态。右侧节点抽屉展示Prompt、素材、Task、媒体、审核和attempt；
底部只在选中视频节点时展开单轨时间轴。

初始成片、整条重生成和AI区间编辑分别形成不可变revision。时间轴可选择0.5～13秒，
默认吸附稳定镜头边界；选区不能跨来源Clip。区间编辑使用Ark源视频和前后边界帧生成一个
候选片段，本地只替换画面并保留基础视频完整音轨。候选通过人工审核前不替换正式视频，
任意旧版本都可比较或回退。

## 7. 失败恢复

- Seedream同步超时可按配置自动重试一次，并明确记录潜在重复计费。
- Seedance监看窗口结束不等于任务失败；已有Task ID可继续查询。
- Seedance创建结果未知时冻结Step，通过任务列表人工对账绑定。
- 普通失败、过期或取消只能在具体节点显式付费重试，新attempt保留旧证据。
- 重新设计剧情使用`replan-episode`，不重做已成功的其他时段。
- 整条成片问题使用节点`regenerate`；局部错误使用时间轴区间编辑。两者都需要新的付费
  确认，且不覆盖旧Prompt、Task ID、媒体或审核。
