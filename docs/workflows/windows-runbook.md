# Windows 运行手册（V5）

## 配置与启动

```powershell
uv sync --extra dev
uv run alembic upgrade head
uv run cvg doctor
uv run cvg api --host 127.0.0.1 --port 8765
```

第二个终端启动持久任务 Worker。开发环境默认只启动一个 Worker，确保付费任务顺序执行：

```powershell
uv run cvg-worker --concurrency 1 --poll-seconds 1
```

第三个终端启动前端：

```powershell
npm --prefix web run dev
```

访问 `http://localhost:5173/canvas`。首次升级前先关闭旧 API/Worker，避免 Windows 锁定
`.venv\\Scripts` 中的可执行文件；升级完成后再按上述三个终端顺序启动。

API 默认监听 `0.0.0.0`，开发前端按上面的 `--host 0.0.0.0` 启动后也可从局域网访问；
系统不增加 IP 白名单、登录或管理员鉴权。请仅在您信任的局域网与防火墙边界内运行。

运行时固定使用真实 Ark 网关，不提供 Provider/Fake 切换。页面点击验收若要求
“不调用 Ark”，只检查只读页面、配置保存、Prompt 预览和本地操作，不点击付费确认按钮。
Ark Key 未配置时仍可浏览和编辑项目，但所有付费按钮会提前禁用。

启动后可在 Web 左侧“系统设置”选择服务端白名单中的规划、图片、视频和审稿模型，
以及 480p/720p 与语义审稿开关。Key 和 Endpoint 仍由服务端 `.env` 管理，不返回浏览器。

FFmpeg 与 FFprobe 推荐安装到系统 PATH；`.env` 中的 `FFMPEG_PATH`、`FFPROBE_PATH`
可以留空。有效显式路径优先，失效显式路径会报告警告并回退 PATH。

## 升级到 0018 并修复 Canon

从现有 V4 直接迁移到 V5，然后按清单校验并重链 11 张批准 Canon。命令重复执行幂等，
任何源文件哈希不一致都会拒绝修改数据库：

```powershell
uv run alembic upgrade head
uv run cvg canon-repair --source-dir "风格定稿/Canon-v1"
uv run cvg doctor
```

迁移最终应显示当前 Alembic head（本版本为 `0024_durable_task_events`）；`doctor` 分别报告数据库、Ark、FFmpeg、
FFprobe、视频生成和本地合成状态。

## Web 操作

1. 创建项目：一句话主题可先运行剧情扩写；完整剧情可直接保存。
2. 选择单片段或填写 2～6 个多片段目标数。完整剧情可直接运行分镜，也可按需运行剧情诊断和重写；每次 LLM 调用单独确认费用。
3. 运行分镜导演，在建议表单中编辑造型、环境、姿态、构图、片段标题、2～4 个编号子镜头和时长后接受。
4. 在 Canon 页面确认 5–7 岁短发儿童、灰白猫和画风文本/参考；旧项目引用异常时点击“恢复 Canon 引用”。
5. 打开“视觉资产准备”，先运行 AI 规划，再逐项选择生成、上传、已有资产或跳过。环境、服装和关键道具图逐张确认费用；全局 Canon 保持只读。
6. 批准所需视觉资产并加入场景参考包；再打开场景视觉基准工作台，编辑草稿、检查 Prompt 后按需生成。它不是视频首帧，也不阻断视频。
7. 在顶部点击“生成新候选/重试生成”，提交后可立即关闭工作台；在版本画廊中大图查看、批准、拒绝或重新选择历史视觉基准。
8. 为每个片段选择关闭、只继承造型、完整参考或派生锚点；保存后逐次选择“仅保存”或付费 LLM 分析。
9. 逐项勾选 LLM 字段或正文候选，并编辑/接受开场静态画面稿；过期 Revision 必须重新分析。右侧“实际参考图”分别检查锚点和视频输入的真实 `@图片N` 顺序、来源与职责。
10. 选择纯文本、已有图片或生成新锚点；`derive_anchor` 必须先批准锚点。视频预览在首帧模式下应只显示 1 张批准锚点，不能同时出现普通参考图；确认 Seedance 费用后任务进入全局任务中心，页面可继续操作。
11. 批准视频会本地抽取尾帧；下一片段可采用，来源视频变化时旧尾帧会标为过期。
12. 重做只影响当前片段，旧 attempt 和媒体保留；批准片段可合成总片或区间重拍。

## 恢复边界

- 左侧“全局任务”统一查看排队、Provider 生成、等待审核、失败和服务重启待恢复状态；运行中媒体尚未落盘时，也会出现在片段“锚点与视频版本”页。
- 带 Provider Task ID 的 queued/running 视频由独立 Worker 按 `next_retry_at` 续查；任务中心只消费 SSE 和展示状态，不在线程内重新提交。
- 已有视频 Task ID：点击“继续查询原任务”。
- `submission_unknown`：点击“按 Provider ID 对账”，不得直接重做；普通 running 状态无需人工恢复。
- 图片同步超时：供应商无持久 Task ID；再次生成前需接受潜在重复计费。
- Canon/视觉基准显示 HTTP 404：查看资产 ID；`contentReady=false` 或 `legacy:` 时执行
  `cvg canon-repair`（Canon）或重新上传项目图片。不要把旧机器绝对路径写回数据库。
- 视觉基准生成返回 409：页面草稿 Revision 已过期，重新打开工作台、预览并保存后再提交。
- 编辑或 Prompt 预览不收费；生成、重新生成和区间重拍均逐次确认费用。
- 片段保存不收费；`/assist` 必须再次明确确认。分析超时只记录失败，不回滚已保存草稿。
- 尾帧不可用：先检查 `cvg doctor` 的 FFmpeg 状态；批准记录不会因抽帧失败而回滚，可在下一片段重新采用时重试。

## 本轮最终验收边界

全部功能落盘后只执行一次浏览器点击链路：分别走主题扩写和完整剧情、接受分镜、跳过或生成视觉
基准、打开独立片段路由、核对三种 Provider 输入模式、版本历史、任务中心、尾帧和本地成片。
验收使用 fake 网关并记录主要聚合接口响应时间；不新增大量测试文件，不执行真实 Ark 调用。
