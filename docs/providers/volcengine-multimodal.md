# 火山方舟多模态能力与Prompt基线

本项目以仓库内五份火山方舟PDF和`docs/SKILL.md`为开发依据。运行时不解析PDF，
能力边界由代码中的版本化档案和测试固定。

## 当前启用模型档案

```text
ARK_VIDEO_MODEL=doubao-seedance-2-0-mini-260615
# 或 doubao-seedance-2-0-260128
ARK_IMAGE_MODEL=doubao-seedream-5-0-260128
ARK_VIDEO_RESOLUTION=720p
```

Mini与完整Seedance 2.0各有显式能力档案，由`.env`选择，不做运行时自动升级。
当前两个档案使用相同的产品输入边界；任务快照和幂等哈希保存实际模型，避免切换
模型后错误复用旧收费任务。Fast或其他模型必须先新增能力档案和请求快照测试。

## 当前Seedance输入边界

- 产品视频时长为8～15秒整数；供应商能力为4～15秒。
- 当前输出只允许480p或720p、9:16、原生音频和关闭水印。
- 多模态参考最多9张图片、3个视频、3个音频。
- 不支持纯音频，也不支持只有文本和音频而没有视觉素材。
- 参考视频和参考音频各自必须为2～15秒。
- 单素材不超过30MB，请求素材总量不超过64MB。
- 输入图片边长为300～6000像素，宽高比为0.4～2.5。

业务层进一步限制一次多模态任务默认最多使用5项重要素材。素材越多不等于控制
越强；弱相关或冲突输入会分散模型注意力。

## 三种视频输入模式

### `multimodal_reference`

默认模式。人物、猫咪、画风、元素、动作和声音素材统一使用`reference_image`、
`reference_video`或`reference_audio`。关键帧也可以作为普通参考图，并在Prompt
中声明为语义开场或结尾。

该模式更适合同时保持角色身份、画风和动作意图，但不承诺输出首尾帧与参考图逐像素
一致。

### `strict_first_frame`

只发送一张`first_frame`。适合开场构图必须精确的内容，不混入其他参考媒体。

### `strict_first_last`

只发送`first_frame`与`last_frame`。适合开场和结果状态都必须准确的内容。人物、
猫咪和画风应先由Seedream融合进两张已经
通过技术和语义审核的关键帧。

“存在包含或交接”本身不会自动升级为严格首尾帧。多次交接或跨镜头互动只记录渲染
风险；只要VisibleWorldPlan状态自洽，默认仍允许单次成片，最终由实际视频审核判断。

## Prompt方言

Seedream使用`图1`、`图2`描述输入图用途。

Seedance使用：

```text
@图片1
@视频1
@音频1
```

素材编号必须与Ark content数组顺序一致，裸数据库Asset ID不得进入Prompt。

Seedance执行Prompt固定为：

1. 输出、二维画风与素材绑定。
2. 人物、猫咪、外观和单一空间。
3. `镜头1/镜头2/镜头3`顺序动作，每镜一种运镜。
4. 可见世界状态与切镜连续性。
5. 原生声音和最多6项去重硬禁止。

不输出`00:00-00:03`等绝对时间码。视频总时长由API的`duration`参数决定，Prompt
只表达先后和相对节奏。每个动作使用结构化`actorId`，严格帧模式不输出没有实际
媒体绑定的主体别名。目标700～1200中文字符，超过1400警告、超过1600阻断。

## 语义资产与审核

Seedream输入不是按`role`任取最近资产，而按`semantic_key`选择最新已批准版本：
人物/猫咪视角、基础线条、室内或户外画风，以及必要的元素/场景资产。默认3～5张，
`legacy:*`不会自动复用。

关键帧默认使用`semantic_auto`：先检查9:16、尺寸、黑边和可读取性，再由Responses
模型检查同一中性儿童、同一灰白猫、二维绘本风格、可见世界状态和空间拓扑。技术
通过不等于语义通过。视频完成后可执行抽帧诊断，但诊断不自动批准最终视频。

## 成片策略

当前产品只使用 Seedance 单次 8～15 秒完整成片。动作阶段和镜头顺序都属于同一次
生成请求，不拆成多个供应商任务，也不提供运行时拼接分支。技术 QC 通过的原始 MP4
直接保存；FFmpeg 仅保留抽帧诊断用途。

## Seedream 5.0 Pro

官方Pro模型支持1K/2K、最多10张参考图以及`<point>/<bbox>`交互编辑，适合局部
文字、道具或定位修复。当前用户选择继续只使用Seedream Lite，因此本项目仅记录
该能力，不包含不可执行的Pro分支。
