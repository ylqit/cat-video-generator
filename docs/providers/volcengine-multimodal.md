# 火山方舟视觉锚点与Seedance延展基线

运行时不解析PDF或网页，能力由当前代码档案固定：

```text
ARK_IMAGE_MODEL=doubao-seedream-5-0-260128
ARK_VIDEO_MODEL=doubao-seedance-2-0-mini-260615 | doubao-seedance-2-0-260128
ARK_VIDEO_RESOLUTION=480p | 720p
```

## Seedream

图片接口只生成单张定妆图或开场锚点。定妆图融合定稿人物和画风；开场锚点融合
定妆图、猫咪视角、场景画风和至多一张关键道具图。每张图单独技术检查和语义审核，
不生成九宫格或多面板故事板。

## Seedance初始任务

初始视频只发送一张批准开场锚点并映射为`first_frame`。输出9:16、8～15秒整数、
原生音频、关闭水印。人物、猫咪和画风已经由开场锚点融合，不再重复直喂多套Canon。

## 官方视频延展

只有配置的完整模型`doubao-seedance-2-0-260128`进入当前延展能力档。延展请求只
发送上一版视频并映射为`reference_video`，Prompt明确使用“向后延长@视频1，从末尾
状态继续，不重演前文”。Mini不会被自动升级；不支持时在创建收费Step前失败。

项目把16～30秒内容编译为一次初始任务和一次续写，把31～45秒内容编译为一次初始
任务和两次续写。官方标准API中的`reference_video`返回指定`duration`的新视频，而不是
包含原片的累计文件；这一点已经通过真实任务验证，也与官方教程中的“再次编辑”示例一致。

因此每个供应商结果先按本区段8～15秒独立执行技术QC，最终再使用FFmpeg concat demuxer
做`stream copy`顺序封装。该步骤不重新编码、不改变画面或声音，也不恢复逐镜独立生成、
multi-clip创作编排或转码兜底。区段编码参数不兼容或累计时长不合格时显式失败。Ark task
已经成功但本地QC/封装失败时，可用原task ID重新落盘，不创建新attempt或重复收费请求。

## 恢复边界

视频创建成功后持久化Task ID。查询超时只暂停本地监看；服务重启或用户点击继续查询
仍使用原Task ID。创建阶段超时且没有Task ID进入`submission_unknown`，只能列出Ark
近期任务供人工对账，不能自动重发。

Seedream是同步图片接口，没有可查询的持久任务ID；超时自动重试次数由`.env`控制，
默认最多一次，并保存重复计费风险。
