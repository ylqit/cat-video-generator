## 1. 行业通行管线分层模型

外部 AIGC 漫剧 / AI 短剧平台在生产架构上已高度收敛为五层：

```
L5 发布层    平台适配（9:16/时长/封面）、数据回收
L4 合成层    剪辑、字幕、配音/对口型、BGM、音效
L3 镜头层    关键帧（文生图，人工把关）→ 逐镜头视频（i2v）→ 抽卡筛选
L2 资产层    角色库（参考图/三视图/LoRA）、场景库、道具库、风格 LoRA   ← 一致性的根基
L1 叙事层    选题 → LLM 大纲 → 分场脚本 → shot list（含世界状态/角色小传）
```

**核心洞察：一致性不是靠生成模型解决的，而是靠 L2 资产层 + L3 关键帧关卡解决的。**
所有平台级功能（主体参考、多主体绑定）本质都是把 L2 资产注入 L3 生成过程。

## 3. 关键行业共识

1. **逐镜头生成 + 剪辑合成，无人用单次生成做完整叙事内容** [行业共识]。即使长视频模型
   存在（Sora 60s、可灵续写至 2 分钟、SkyReels-V2 宣称无限时长 [官方宣传，需验证]），
   整片一次生成在可控性、局部修改、良品率上均不可行。
2. **关键帧先行、图生视频为主** [社区实践高度一致]：先锁定每镜头关键帧（此时角色/场景/
   画风都可把关），再用 i2v 让画面动起来。一致性和良品率显著高于文生视频直接出镜头。
3. **单镜头典型 4-10 秒**；一集 1-2 分钟漫剧约 15-30 个镜头 [社区实践]。
4. **镜头衔接三种手段**：首尾帧指定（可灵 [官方功能]）；**尾帧复用**（上镜头最后一帧作
   下镜头 i2v 首帧）[社区实践]；视频续写/延长 [官方功能]。
5. **抽卡率是成本结构核心**：社区普遍报告每镜头需生成 5-20 次才得可用片段 [社区实践]。
   通行降本：低分辨率试生成→选帧→高清重生成；局部重生成（废一个镜头只废几秒）。
6. **角色一致性技术按普及度**：平台原生主体参考 > 角色 LoRA（2D 漫剧事实标准）>
   角色三视图 > IP-Adapter/FaceID 等开源方案 > 后期换脸（有争议）。
7. **场景/道具一致性 = 资产库思维**：场景标准背景图入库复用；多主体参考同时绑定
   角色图+场景图+道具图（Vidu [官方功能]）；自建管线用 ControlNet 锁空间结构。
8. **2D 漫剧与写实短剧管线分叉**：2D 漫剧以风格 LoRA 为核心资产，走"静帧漫画格+微动效+
   配音"，成本极低、一致性极高；写实短剧逐镜头 i2v，依赖视频模型身份保持，成本高、
   抽卡率高 [社区实践]。
9. **显式"世界状态/角色记忆"在平台侧基本缺失** [推断]；跨集连续性靠社区自建
   （角色卡数据库 + 剧情摘要 RAG + 多智能体编剧），多为实验性。

## 4. 本项目架构 vs 行业通行做法（分层映射）

本项目此前的优化计划是按 bug 逐条打补丁；映射到行业五层模型后可以看出，
那些补丁实际是在**补齐通用架构中缺失的层**，并且方案 C 就是行业默认形态：

| 行业层 | 通行做法 | 本项目现状 | 差距/补丁的归位 |
|---|---|---|---|
| L1 叙事层 | LLM 编剧；IP 改编；平台侧无世界状态 | 4 次导演调用（DayBrief+3 时段）= 已超过多数平台；但剧情 100% LLM 即兴，`recent_summaries` 未接线 | **事件池抽签 + 冷却期 + 状态摘要接线** = 补齐叙事层的数据驱动；日更连续世界状态是本项目**超出行业**的差异化机制（对齐 sowii 三层模型） |
| L2 资产层 | 角色库/三视图/LoRA、场景库、道具库、风格 LoRA | Canon 三角色（person/cat/style）参考图 = 已有骨架；无场景库/道具库；画风无文字锚点 | **scene_inventory 道具台账** = 道具库的轻量动态版；**画风/人设文字锚点** = 风格触发词的通用做法；后续可加场景参考图库（scene 角色资产已预留） |
| L3 镜头层 | 关键帧先行 → 逐镜头 i2v → 抽卡筛选；尾帧复用衔接 | 单次 12 秒多镜头生成，中间镜头零图像锚点 = **偏离行业共识的最大差距** | **方案 C（逐镜头分段 + 真实尾帧链接 + 段级 QC）= 收敛到行业默认形态**；manual/technical_auto 关键帧审核 = 行业的"关键帧人工关卡" |
| L4 合成层 | 剪辑 + 配音/字幕/BGM | 无合成层 | **ffmpeg concat 自动拼接** = 合成层最小实现；原生音频免配音（无对白定位使本项目天然省掉对口型环节） |
| L5 发布层 | 9:16/封面/数据回收 | 9:16 已固定 | 暂未需要 |
| QC 贯穿 | 抽卡筛选（每镜头 5-20 次）；关键帧人工把关 | 硬门（rules.py 四道门）+ 关键帧双模式审核 + 段级 QC（方案 C）= **比行业通行做法更系统化** | 需补：段级重试预算上限（对齐"抽卡预算"纪律）、低分辨率试生成→高清出片的降本路径（480p 档位已预留） |

### 5-A.2 火山剧创（volcengine.com/product/dramart）— 已核实，高价值参照

**火山引擎（字节）企业级 AIGC 短剧一站式创作平台，2026-05-21 公测上线 1.0。**
对本项目价值最高——它与我们**绑定同一族模型（Seedance 2.0 + Seedream 5.0 lite）**，

已核实事实：

1. **官方管线 = 剧本解析 → 资产设定 → 分镜生成 → 视频合并**，
   自研"多智能体协同"架构，端到端覆盖剧本到成片
   [评测核实，https://www.sohu.com/a/1027150236_121864780]。
   官方文档站结构：剧本生短剧、重制工坊、项目、资产、团队管理、用量统计、
   标准剧本格式参考 [官方文档目录，https://www.volcengine.com/docs/87744]。
2. **资产设定（L2）**：系统内生成**角色三视图 + 音色**、场景、道具资产；
   可上传自有资产；团队资产沉淀/共享复用 [评测核实]。
3. **分镜生成（L3）**：分镜提示词、角色/场景资产绑定均可编辑；支持上传
   本地图片、**视频、视频帧**作参考素材，在提示词中用 **@引用**——
   与本项目 Seedance `@图片N` 方言（docs/providers/volcengine-multimodal.md）同源；
   依托 Seedance 2.0 "全能参考生视频"实现"角色稳定、不变脸、不穿帮" [评测核实]。
4. **分镜拆解 Agent 内置"爆款逻辑"**：镜头调度策略（什么开场留人、什么节奏
   完播率高）来自短剧业务实践，直接写进分镜 Agent 底层决策 [官方披露，经评测转述]。
5. **企业级定位**：团队权限（导演/分镜师/审核员/外包临时角色）、积分配额与
   消耗明细、虚拟人像/真人人像授权库（合规红线"未授权换脸"）[评测核实]。
6. 行业背景：2026 年 AI 短剧用户预计 2.8 亿、市场规模约 240 亿元（央视财经口径，
   经评测引用）；截至 2026-04 赛道企业 2.2 万家 [媒体报道，需注意为第三方数据]。

**对本项目的校验与启示**：

- **分层管线被官方同族方案完整印证**：剧本解析(L1)→资产设定(L2)→分镜生成(L3)
  →视频合并(L4) 正是本文第 1 节的 L1-L4 模型，本项目改造方向与供应商官方
  最佳实践同向；
- **资产层比我们厚**：角色**三视图**（正/侧/背）+ 音色是我们的 Canon 单图所缺；
  三视图对镜头角度变化大的人设稳定性值得引入（人物/猫各补侧、背面 Canon 图）；
- **分镜参考素材含"视频帧"**：官方支持把视频帧作为分镜参考——佐证方案 C
  "真实尾帧作为下段输入"就是官方能力形态；
- **差异化仍在**：火山剧创/趣吉都是**项目制、人在环路（每节点保留编辑权限）**；
  本项目的日更连续世界状态（L1 数据层）与 technical_auto 零人工全自动链路
  是两者都没有的形态。

**开源侧对本项目的三点校验**：

1. **分层编剧（总导演→时段导演）有学术与开源双重印证**（Dramatron 分层结构、
   FilmAgent 多 agent 分工）——本项目 L1 架构方向正确，缺的不是结构而是
   数据输入（事件池/世界状态）；
2. **"规划层与渲染层分离"是学术共识**（MovieAgent/MovieDreamer 均如此分层）——
   方案 C 的逐段渲染 + 链接属于渲染层工程，不应反过来污染叙事层设计；
3. **全自动流水线的工程范式可参考混剪系开源项目**（MoneyPrinterTurbo 类）：
   任务台账、素材可回放、失败可断点续跑——本项目 DB-first 设计已具备，
   方案 C 的段循环应保持同一范式。

## 5. 结论：通用化后的改造主线

按行业分层重述本项目改造，不再是"修四个 bug"，而是三条架构主线：

1. **L3 镜头层归位（原方案 C）**：逐镜头分段生成 + 真实尾帧链接 + 自动拼接 +
   段级 QC。这是与全行业共识对齐，不是特例发明。
2. **L1+L2 数据化（原事件池/场景清单/锚点）**：叙事层事件抽签、资产层道具台账与
   风格锚点——把"靠模型自觉"全部改为"靠数据与资产注入"，正是一致性问题的行业通解。
3. **成本纪律对齐行业**：段级重试预算上限、480p 试生成 → 720p 出片、
   图生视频优先于文生视频。

## 6. 对"一人一猫日更 vlog"场景的适配原则（行业经验的本地化）

1. 12 秒 = 1~3 个镜头，恰好落在单镜头 4-15s 生成区间，衔接问题规模比漫剧
   （15-30 镜头/集）小一个数量级——方案 C 在本场景是轻量实现。
2. 无对白定位 → 天然省掉行业管线中最重的对口型/配音环节，原生音频即可。
3. 日更连续性（世界状态/道具台账/事件冷却）是行业平台普遍缺失、而本场景
   最有价值的机制——这是超越"漫剧工具"的差异化所在。
4. 画风目标为 2D 插画风 → 可借鉴 2D 漫剧"风格资产为核心"的低成本思路：
   风格参考图 + 风格锚点文本先行，后续如需更强控制再评估风格 LoRA。
